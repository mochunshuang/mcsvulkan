# 01 · 概念

十个概念，分三层。**上层只描述结构，中层只做推导，下层只执行。**

```
类型层（你写）      kind   source   leaf   组合子
                     │        │       │
                     └────────┴───┬───┘
                                  ▼
推导层（编译期算）        footprint → relation → cell（+ 裁决顺序）
                                  ▼
运行层（每帧跑）          claim 槽 → verdict → stage / arena
```

---

## 类型层：你写的东西

### 1. `kind<"click">` —— 语义事件的身份

- **定义**：一个语义事件的**类型**。全库范围内唯一。
- **为什么需要**：裁决问的是“这两个申请是不是同一个说法”，这需要身份，而不是数据。
- **不是什么**：不是事件对象，不带坐标/按钮/时间。载荷是**另一个**问题（v2 未决）。
- **约束**：每个 kind 恰好一个生产者（见 [L6](02-laws.md)）。

### 2. `source<"mouse.left">` —— 物理通道的身份

- **定义**：一个独立的输入源。左键、右键、键盘各是一个 source。
- **为什么需要**：它是“两个假设会不会相遇”的**唯一**判据。
  不同 source 的假设永远不会同时成立，所以永远不需要裁决。
- **不是什么**：不是窗口，不是设备句柄，不是 lane 的实例号。
  它是编译期常量；运行期多指（pointer id）是 v3 的事。
- **推论**：跨 source 的关系没有意义 ⇒ 声明它就是编译错误。

### 3. `leaf<K, S, Fsm>` —— 生产者

- **定义**：一个 FSM + 一个 kind + 一个 source。**唯一实现 `step` 的角色。**
- **为什么需要**：识别是状态机的事；把它和裁决分开，才能各自单测。
- **不是什么**：不是“识别器集合”，不是可组合的容器。它只有一个 kind。
- **接口**：`step(frame, now) -> {idle, active, done, aborted}`，`reset()`。
  这就是 Qt 的 `event()` 那个 override 点。

### 4. 组合子 —— 你写结构的语法

| 组合子 | 结构含义 | 生成的边 |
|---|---|---|
| `all_of<a,b,…>` | 并行：没有因果关系 | 无 |
| `one_of<a \| b>` | 同源互斥：先到先得 | a×b 的**对称**边 |
| `refines<a, b>` | b 是 a 的细化（双击之于单击） | a→b 的**有向**边 |
| `times<d, a>` | 时窗：只改时序 | 无 |

- **关键**：关系是**组合子生成的**，你永远不手写 `await` / `cancels`。
- **不是什么**：组合子不是“运行时容器”。它们只持有孩子，`plan()` 是编译期函数。

## 推导层：编译期算出来的东西

### 5. `footprint` —— 一棵树的静态摘要

- **定义**：`{kinds[], relations[]}`。树的一个同态像。
- **为什么需要**：让你可以在不运行的情况下问“这棵树会不会打架”。
- **不是什么**：不是运行期数据。它只存在于 `consteval` 里，最后落成 `static` 数组。

### 6. `relation` —— 两种，别混

| | `after`（细化） | `excludes`（互斥） |
|---|---|---|
| 方向 | 有向：a 必须等 b 失败 | 对称：谁先到谁赢 |
| 语义 | “b 比 a 更具体” | “a 与 b 是同一个时刻的两种解释” |
| 生成者 | `refines` | `one_of` |
| 运行期表现 | a 在 b 活着时不能赢；b 赢了 a 让位 | 一方赢，另一方立刻让位 |

- **不是什么**：不是优先级，不是权重，不是超时。关系只有这两种。

### 7. `cell` —— 裁决的最小单位

- **定义**：同 source 内、关系图的**连通分量**。
- **为什么需要**：这就是“细分”。cell 之间无共享变量，所以整体语义 = 各 cell 语义的**积**。
- **不是什么**：不是 source。一个 source 上可以有好几个 cell
  （比如鼠标上的 `{click,dbl,drag}` 和 `{scroll,zoom}` 互不相干）。
- **推论**：`|cell| = 1` 时它退化——没有裁决器、没有延迟（见 [L5](02-laws.md)）。

## 运行层：每帧跑的东西

### 8. `claim`（在 v1 里退化成“槽”） —— 一条活着的假设

- **定义**：`{kind, alive, deferred, begin, end}`。
- **为什么需要**：裁决的对象是**申请**，不是识别器。同一个识别器在不同时刻的两条申请互相独立。
- **不是什么**：不是识别器，不是事件。v1 里它没有身份（handle），
  因为“一 kind 一生产者”保证了一个 kind 至多一条活着的申请。

### 9. `verdict` —— 答复

- **定义**：只有两种。
  - `accepted`：你就是这次交互的解释。
  - `superseded`：更具体的（或先到的）赢了，你让位。
- **不是什么**：不是三种。**“自己放弃”不是判决**——
  没发生的交互不该通知任何人（这是 v1 写完后被 S4 纠正的，见 [04](04-design-space.md)）。

### 10. `stage` / `ui` / `sink` —— 裁决台、舞台、收件人

- **`stage<cell>`**：一个 cell 的存活表。一 kind 一槽，无 handle、无容量、无堆。
- **`ui<Tree>`**：树 + 每个 cell 一个 stage + 每个 kind 一个 sink。对外六个名字：
  `ui`（装配）、`bind`（延迟绑定）、`feed`（**唯一的输入动词**）、
  `events` / `to_string`（观测）、`describe`（打印结构）。
  刻意**没有** `play` / `run` 这类批量入口：真实输入是一帧一帧来的，
  脚本回放属于库外的测试工具。
- **`sink`**：**两字函数指针** `{void* self, void(*)(void*, const event&)}`。
  `bind(arena)` 把它填成 `{&arena, &on_event<...>}`，于是 accepted 会落到
  `make_aggregate` 的 `method<"on_<kind>">` 里，handler 能改 arena 自己的数据。
- **不是什么**：不是调度器（不排队、不延迟、不重试），
  也不是 arena（arena 是 `make_aggregate` 造的，uhi 不认识它的类型）。
